# 采集原理与指标

控制机通过系统 OpenSSH 将内置的 `probe.sh` 输入给远端 `sh -s`。脚本不上传文件，不安装依赖，不修改远端配置。每次连接在约 1 秒间隔内读取两次 CPU 和网络计数，计算该时间窗内的利用率和速率。

| 指标 | 来源与语义 |
| --- | --- |
| CPU | `/proc/stat`，两次采样的非空闲时间占比；不重复计入 guest 时间 |
| CPU 数 | `/proc/stat` 中逻辑 CPU 数 |
| 内存 | `/proc/meminfo`，使用率为 `(MemTotal - MemAvailable) / MemTotal` |
| Swap | `/proc/meminfo`，总量、已用量与百分比；无 Swap 时为 0 |
| 系统负载 | `/proc/loadavg`，1、5、15 分钟平均值 |
| 运行时长 | `/proc/uptime`，以秒为单位 |
| 磁盘 | `df -Pk`，块数量转字节，包含总量、已用、可用、占比和挂载点；过滤虚拟文件系统 |
| 网络 | `/proc/net/dev`，所有非 loopback 接口的累计接收和发送增量除以实际时间间隔 |
| NVIDIA GPU | `nvidia-smi`，设备编号、名称、利用率、显存已用/总量、温度 |

网络接口求和可能在 bridge、veth、bond 等复杂拓扑上重复统计流量；这是接口吞吐量合计，不是物理链路计费值。计数器重置时速率归零。磁盘使用率采用 `df` 报告的值，可能受预留空间影响。

无 NVIDIA 驱动或命令时，GPU 列表为空。GPU 字段不支持或设备被占用时返回 `null`，前端显示 `—`。

每台服务器的最近 60 次采样保存在内存中。采集失败会追加空值，当前指标清空，仍保留最后成功时间与旧历史，避免将过期指标误当作当前状态。页面检测到长时间未更新也会明确提示。
